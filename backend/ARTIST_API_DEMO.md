# ReelDrama Artist API — First Demo (v1)

> Status: API contract/demo specification. These routes are proposed and are not live until the backend implementation is merged and deployed.

## Purpose

A creator or production house keeps its own content-management system and authorized video hosting. ReelDrama does not need an in-app video-upload screen. The creator's system sends series/episode metadata and an authorized HTTPS playback URL to ReelDrama's Artist API.

## Demo tenant

- Creator display name: Himalaya Studio Demo (fictional)
- Demo series: Gaunko Katha (fictional)
- All sample URLs below are placeholders. Do not use them for playback.

## Authentication

Every creator receives a unique API key. Send it in the request header:

```http
X-Creator-Key: rd_live_REPLACE_WITH_ISSUED_KEY
Content-Type: application/json
```

Keys must be generated by an authorized ReelDrama administrator, shown only once, stored hashed in the database, and revocable/rotatable. Never put a creator key in an Android APK, public website, URL, or Git repository.

## Proposed endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/v1/creator/series` | Create or update a creator-owned series |
| POST | `/api/v1/creator/series/:seriesId/episodes` | Add or update an episode in that creator's series |
| GET | `/api/v1/creator/catalog` | List only this creator's submitted content and review status |
| POST | `/api/v1/creator/webhooks/test` | Test creator integration (optional later feature) |

These endpoints are a proposed contract, not a claim that they already exist.

## Expected response

```json
{
  "success": true,
  "status": "pending_review",
  "message": "Content received. It will appear in ReelDrama after rights and playback verification.",
  "seriesId": "REELDRAMA_SERIES_ID",
  "episodeId": "REELDRAMA_EPISODE_ID"
}
```

## Publication workflow

1. Creator sends series/episode metadata and an authorized playback URL.
2. ReelDrama validates the API key, creator ownership, fields, URL format, and duplicate external IDs.
3. New content starts as `pending_review`; it is not visible in the public Android catalogue.
4. ReelDrama verifies distribution rights, territory, playback access, artwork, and content details.
5. Only approved content is published through the existing public catalogue API.
6. A webhook or scheduled sync can notify creators about review status; near-real-time updates can be added after the first integration works.

## Security and rights rules

- One creator key can access only that creator's records (tenant isolation).
- Store only a secure hash of API keys; support revocation and rotation.
- Enforce request validation, rate limits, audit logs, and idempotency using the creator's external IDs.
- Accept only HTTPS playback URLs from approved hosts. Prefer expiring signed playback URLs.
- Never download or mirror a creator's video just because a URL was supplied.
- A YouTube/TikTok public link does not itself grant OTT redistribution rights.
- The creator must confirm the rights and territories they are licensing to ReelDrama; publication requires manual approval in the first demo.

## Important implementation note

The current ReelDrama backend has existing Drama/Episode models and public catalogue routes. The next implementation step is to extend those models safely with creator ownership and publication review fields, add a dedicated creator-key authentication middleware and routes, and preserve all existing viewer endpoints. No existing files should be deleted as part of this first demo specification.
